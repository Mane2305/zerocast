# Saved demo bundles

The app's primary demo cards use `retail/` and `manufacturing/`, supplied by the backend precompute script. Retail is real UCI Online Retail II history (UK gift retail, grouped into five product families), with saved 14-day forecasts and a `histories.json` array of contract-shaped SeriesHistory objects. Manufacturing is real India cement index history, with a saved 12-month forecast. Both include health, history, forecast, review, and factors JSON. Opening them reads saved files; it does not run inference. Attribution links appear in the forecast's source details. The Factor check demo uses the real manufacturing factors.

The refreshed bundles include `Dataset.additive` and `total_distribution.aggregation`: retail uses sums; cement uses backend-computed period means. The frontend never divides a supplied mean by the horizon. Older synthetic fixtures explicitly use additive/sum metadata to preserve their original illustrative values.

These supplied bundles are unchanged. Their timezone-free timestamps currently fail the OpenAPI `date-time` format; run `npm run demos:validate -- retail manufacturing` to reproduce. The UI preserves source calendar dates and can display the saved results, but strict contract compliance still requires backend serialization fixes and regenerated output. See `frontend/README.md` for the integration handoff. Do not replace these outputs with generated mock values.

## Synthetic frontend fixtures

`retail-mock` and `manufacturing-mock` contain invented, deterministic examples for F2. They are not Favorita data, India cement statistics, or model predictions. No third-party dataset is redistributed.

Run `npm run demos:generate` to regenerate and `npm run demos:validate` to check the shared OpenAPI schema. Each directory contains `dataset.json` (Dataset), `history.json` (SeriesHistory), and `forecast.json` (ForecastResult). Total percentiles come from synthetic sample-path totals. `latency_ms: 0` denotes no model invocation and is not displayed as model speed.

B6 can add real precomputed bundles in these contract shapes. Add new presentation metadata in `src/lib/demos.ts` and update explicit synthetic labels before exposing real data. Keep these mock IDs separate so provenance is unambiguous.

## F7 review illustrations

`retail-mock/review.json` and `manufacturing-mock/review.json` are explicitly synthetic illustrations generated by `scripts/generate-review-demos.mjs`. They reuse dates and actual values from the synthetic history files, with invented expectations, coverage and illustrative calendar tags. No replay model or holiday lookup was run. Regenerate them after changing the mock history. They use the exact `ReviewResult` shape and validate against the shared contract. Demo annotations are read-only; saved user notes use uploaded dataset endpoints.

## F8 factor illustration

`factors-mock/dataset.json` and `factors-mock/factors.json` are a separate invented dataset summary and FactorResult, generated by `scripts/generate-factor-demo.mjs`. They illustrate all four verdicts with synthetic association and backtest metrics. No statistical test, model backtest or real data processing was performed. Both files validate against the shared contract. This fixture does not add factor columns to the existing factor-free retail/manufacturing demos.
